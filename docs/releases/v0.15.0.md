# v0.15.0 — Patroni Backup And Point-In-Time Recovery

## Summary

Back up the current Patroni primary and archive WAL across leader changes.
Recover a pre-failover backup to a selected point on the promoted timeline in
a separate PostgreSQL container, including data removed from both live nodes.

## Highlights

- Add pgBackRest `2.59.1` to the Patroni image and a dedicated shared repository.
- Enable WAL archiving at bootstrap and provide an authenticated DCS update for existing clusters.
- Reuse backup and restore scripts with Patroni primary selection and offline repository inspection.
- Require an explicit destination timeline for Patroni time recovery.
- Restore without live data mounts, network, DCS access, or write access to the repository.
- Reject incomplete recovery targets and preserve existing target data until explicitly discarded.
- Verify exact rows, post-failover WAL, deleted-order recovery, and retained restored writes.

## Validation

The disposable recovery scenario upgrades archive-disabled DCS settings, takes
a full backup, promotes a replica, and archives writes on the new timeline.
After removing the live services, it rejects an unreachable target and then
recovers the intended state from the original backup and archived WAL.

## Scope

The restored database is standalone and does not replace the live Patroni
primary or restore etcd. Backup and database volumes share one Docker host.
Off-host storage for this runtime, scheduled Patroni backups, application
cutover, and additional tablespaces are outside this change. Existing local/S3
runtime commands keep their own repositories and data volumes.
