# v0.3.0 — Point-In-Time Recovery

## Summary

Restore PostgreSQL to a selected UTC time before accidental deletion, preserving
committed post-backup orders while excluding later transactions.

## Highlights

- `make restore-time` selects a full pgBackRest backup and an explicit UTC timestamp.
- Recovery runs in the existing isolated service with a dedicated data volume,
  read-only backup repository, and WAL archiving disabled.
- Invalid timestamps and occupied targets are rejected. Recovery fails when
  archived WAL cannot reach the requested time.
- The operations guide covers the deletion exercise, target selection, inspection,
  shutdown, resume, and retry.

## Validation

`make check` and `make acceptance` passed locally and in
[CI on the merged main commit](https://github.com/VlrRbn/postgres-disaster-recovery/actions/runs/36751372482).
The acceptance scenario restored all 22 expected orders exactly, excluded the
later transaction, and verified that restored-side writes survived restart.
Source records and repository checksums remained unchanged by PITR.
Existing backup and physical restore checks also passed.

## Scope

Recovery uses local archived WAL on the selected backup's timeline. The database,
backup repository, and recovered instance share one Docker host. Application cutover,
off-host durability, or RPO/RTO measurement are not included.
