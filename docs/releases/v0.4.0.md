# v0.4.0 — Recovery Measurement

## Summary

Measure verified PostgreSQL recovery duration and acknowledged data loss with
explicit workload, fault, and validation boundaries.

## Highlights

- Monotonic timing from restore invocation through exact data checks and a new write.
- Durable host-side acknowledgment journal for a sequential synthetic workload.
- Controlled archive outage followed by a primary crash and archive-only recovery.
- `make restore-latest` with an explicit backup label and selected backup's timeline.
- JSON reports containing loss counts, recovery gaps, UTC boundaries, and source provenance.
- Reproducible acceptance commands and automated report validation in CI.

## Validation

Local acceptance recovered 22 expected rows during PITR. The separate archive-outage
exercise acknowledged ten transactions, exactly recovered five, and identified
five lost acknowledgments. Report tests reject ambiguous recovery frontiers,
modified data, and invalid clock boundaries.

## Scope

The reported RPO gap concerns archive-only recovery with the original source data
unavailable to the recovered instance. Writes are quiesced before the controlled
crash. Recovery duration excludes incident detection, preparation, and application
cutover. The small workload, cached images, and shared Docker host establish
experimental observations.
