# v0.6.0 — External Backup And Clean-Host Recovery

## Summary

Store PostgreSQL full backups and archived WAL in AWS S3, then recover on a fresh
EC2 host with the source stopped, temporary instance-role credentials, and
read-only repository access.

## Highlights

- Dedicated private S3 bucket with verified HTTPS, encryption, versioning, and
  prefix-scoped writer permissions.
- Bundled pgBackRest full backups and WAL archiving, with retention of two full backups.
- Separate EC2 writer and reader instance profiles; instance mode keeps AWS keys
  and session tokens out of the generated pgBackRest config.
- `make s3-restore`, `make s3-restore-time`, and `make s3-restore-latest` reuse the
  existing restore workflow with an explicit backup label and an empty target volume.
- Restored PostgreSQL keeps archiving disabled, publishes no ports, and mounts
  neither the source database volume nor a local backup repository.
- Separate temporary-host Terraform state, SSM administration, required IMDSv2,
  and encrypted root storage, with cleanup that retains backups and identities.
- S3 API acceptance exercises the operational Compose restore service, occupied
  target rejection, and recovered-side persistence.

## Validation

Local checks include 26 unit test methods, shell validation, all Compose models,
and both Terraform roots. The existing local recovery scenarios verify physical
restore, PITR, corrupt-backup detection, missing-WAL rejection, and new writes.
The isolated S3 API fixture verifies retention rollover and recovery of the
oldest retained backup with subsequent WAL.

The live AWS exercise recovered all nine expected rows exactly on a fresh EC2
host while the source remained stopped. The post-backup WAL transaction was
included and the later transaction excluded. A new recovered-side write survived
container recreation. IMDSv1 was denied, the instance config contained no AWS
keys, and actual S3 put/delete requests under the reader role returned
`AccessDenied`. Evidence was exported before all eight temporary resources were
removed. Independent AWS reads confirmed cleanup and retention of the repository
and instance profiles.

## Scope

This release verifies external backup storage and clean-host recovery with
synthetic data. It does not install a backup schedule or automatic failover.
Local profile mode still uses temporary credential snapshots; instance mode
requires reachable EC2 IMDS. Long-duration credential renewal and recovery
objectives including EC2 provisioning are not established. S3 versioning retains
historical object versions; no lifecycle deletion rule is installed.
