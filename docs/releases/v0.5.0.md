# v0.5.0 — Backup Health

## Summary

Detect missing or stale completed full backups and current WAL archive failures
with an on-demand JSON health command.

## Highlights

- `make backup-health` combines backup freshness, repository metadata, primary
  reachability, and active WAL delivery checks.
- Configurable backup-age and archive-timeout limits, with explicit UTC age boundaries.
- Nonzero health failure status and JSON details when a dependency is unavailable.
- Archiver statistics retained for diagnosis without treating historical failures as a current outage.
- Disposable acceptance covers missing backups, stale backups, archive outage,
  recovered delivery, and a stopped primary.
- Updated README and roadmap reflect the published recovery milestones.

## Validation

Local acceptance detects each injected problem, preserves the completed backup
and synthetic order, and returns healthy after archive permissions are restored
and the test primary restarts. Historical archive errors remain visible after
recovery. Unit tests exercise age boundaries, backup selection, invalid inputs,
and refusal of unavailable or disabled primary state.

- [Backup health operations](https://github.com/VlrRbn/postgres-disaster-recovery/blob/v0.5.0/docs/backup-health.md)
- [Backup health evidence](https://github.com/VlrRbn/postgres-disaster-recovery/blob/v0.5.0/evidence/backup-health-acceptance-20261005.md)

## Scope

The health command checks the existing local repository on demand and forces a
WAL switch. It does not install backup scheduling or alert delivery. A healthy
report does not replace backup integrity checks, restore exercises, or off-host
storage.
