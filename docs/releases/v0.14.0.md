# v0.14.0 — Stable Primary Endpoint

## Summary

Add HAProxy to the Patroni runtime so clients can reconnect through the same
address after the PostgreSQL primary changes. Keep PostgreSQL TLS end to end
and verify each Patroni server's identity during role checks.

## Highlights

- Route SQL to a node only after successful HTTPS `/primary` checks.
- Start backends unavailable and close sessions when a backend is marked down.
- Publish only the proxy's SQL port on `127.0.0.1`, defaulting to port `6432`.
- Add `make patroni-endpoint-psql` with a disposable client and private password file.
- Extend PostgreSQL certificates for the shared endpoint, preserving existing CA and keys.
- Pin the HAProxy image to `3.2.26-alpine` and its multi-platform digest.
- Extend the existing Patroni acceptance with routed writes, TLS rejection,
  broken-session detection, endpoint recovery, and quorum-loss rejection.

## Validation

The disposable scenario sends all acknowledged workload inserts through HAProxy,
crashes the primary, verifies that the open SQL session breaks, and opens a new
verified connection to the promoted node at the same address. It also checks
client rejection of plaintext, wrong hostnames, and untrusted certificates;
proxy fixtures reject incorrect HTTPS server identities and CA trust.

## Scope

One HAProxy process and one Docker host remain shared failure points.
Applications must reconnect, handle uncertain commit outcomes, and decide
whether writes can safely be retried. Asynchronous replication can still lose
acknowledged commits. Automatic transaction replay, connection pooling,
application-role provisioning, and Patroni-cluster backup integration are
outside this change. The SQL helper uses the existing administrative identity.
