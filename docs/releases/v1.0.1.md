# v1.0.1 — Runtime Isolation And Acceptance Cleanup

## Summary

Prevent local commands and disposable acceptance cleanup from selecting another
runtime's Compose project. These fixes protect existing database volumes and the
intended WAL archive destination when runtime settings remain exported in the
shell or are passed on a Make command line.

## Highlights

- Local foundation, RPO, backup-health (including scheduling), and pgAdmin acceptance explicitly set `PGDR_REPOSITORY=local` and `PGDR_S3_FIXTURE=0` before installing exit handlers.
- Acceptance startup and failure cleanup use the same temporary local project even when S3 or Patroni settings are inherited.
- pgAdmin, scheduling, and manual replication acceptance clear `MAKEFLAGS`, `MFLAGS`, and `MAKEOVERRIDES` so nested Make retains temporary projects, secret paths, and notification settings.
- The local backend rejects `postgres-dr-s3`, `postgres-dr-patroni`, `postgres-dr-replication`, and their `-*` child project names with exit status `2` before calling Docker.
- Default runtime projects, other valid local project names, and valid backend/project combinations remain supported.
- Eight regression tests cover project selection, reserved-name rejection, and acceptance cleanup using temporary checkouts and mocked Docker commands; the public pgAdmin and scheduling targets run through real Make.

## Validation

Local `make check` passed all 88 Python tests, Bash syntax checks, ShellCheck,
seven Compose configurations, systemd definitions and calendars, and diff
formatting checks. A separate run of all eight isolation regression tests also
passed.

The regression coverage includes 30 combinations of inherited backend/fixture
settings across the four local acceptance scripts and the scheduling variant.
It verifies that a failed startup cleans up only its temporary local project
and preserves the existing configuration represented by the fixture. Reserved
project names are rejected without a Docker call; supported runtime selections
still reach the expected Compose configuration.

Two additional regression tests exercise 12 combinations of command-line overrides
through `make pgadmin-acceptance` and `make schedule-acceptance`, using the
production Makefile. Both tests failed before the nested-Make fix, with all 12
combinations detecting the bypass, and passed afterward. The fixture checks one
temporary project and unchanged temporary backend, secret and alert paths through
startup, nested backup/health jobs, and cleanup. It covers initial and UI startup
failures, successful scheduled jobs, and an injected scheduled backup failure.

These are local validation results. Docker and AWS remain stubbed in the isolation regressions.
The pgAdmin fixture stops before browser checks, and host timers are not used.

## Scope

This patch changes runtime selection and acceptance cleanup safeguards. It
requires no data migration and does not rename existing projects or volumes.
Local invocations using another runtime's reserved project name now fail before
they can reuse its data or change its WAL archive destination.

Replication readiness and the first-start readiness race are outside this patch.
Existing containers, volumes, and runtime configuration were not changed during
validation.
