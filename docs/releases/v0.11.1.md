# v0.11.1 — Consistent Operational Commands

## Summary

Rename operational commands so that database roles, backup checks, timer actions,
and recovery boundaries are clear from their names. Update script dispatch,
systemd units, and the current operating guides together.

## Highlights

| Previous command | Replacement |
| --- | --- |
| `make replication-psql` | `make replication-primary-psql` |
| `make standby-psql` | `make replication-standby-psql` |
| `make replication-promote` | `make replication-switchover` |
| `make s3-info` | `make s3-backup-info` |
| `make s3-check` | `make s3-backup-check` |
| `make s3-health` | `make s3-backup-health` |
| `make scheduled-health` | `make scheduled-backup-health` |
| `make schedule-start` | `make schedule-enable` |
| `make schedule-stop` | `make schedule-disable` |
| `make restore-latest` | `make restore-latest-wal` |
| `make s3-restore-latest` | `make s3-restore-latest-wal` |

The SQL commands select the current primary or standby by database role, even
after a switchover. `latest-wal` replays available archived WAL from an explicitly
selected backup. `schedule-enable` and `schedule-disable` describe persistent
timer activation, including the current user session.

The old names are removed. Direct script callers must also replace
`replication.sh promote` with `replication.sh switchover`, `restore.sh latest`
with `restore.sh latest-wal`, `backup.sh scheduled-full` with
`backup.sh scheduled-backup`, `backup.sh scheduled-health` with
`backup.sh scheduled-backup-health`, and `setup.sh schedule-stop` with
`setup.sh schedule-disable`. Direct `restore-volume.sh` callers must pass
`latest-wal` instead of `latest` for archive-end recovery.

Existing systemd installations need a deliberate
[unit refresh](../backup-scheduling.md#update-installed-units).
Service names, saved schedule configuration, and alert incident state are preserved.

## Validation

Static checks and Python tests cover unit reinstallation while preserving
operator configuration. Disposable scenarios exercise backup and PITR,
archive-end recovery with measured loss, scheduled job locking/failure handling,
and TLS streaming through switchover and rejoin.

See [command acceptance evidence](../../evidence/command-names-acceptance-20261028.md)
for completed checks and their limits.

## Scope

This is a command interface change. Database formats, backup destinations, TLS
settings, replication roles, and notification state keys retain their existing
behavior. Update external automation that calls the old names before resuming
scheduled work. Previously published release notes and evidence retain the
commands used at the time.
