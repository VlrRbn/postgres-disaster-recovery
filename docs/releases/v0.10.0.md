# v0.10.0 — Backup Alerting

## Summary

Add optional Telegram and SMTP notifications to the existing local scheduled
backup and health jobs, with independent channel delivery and saved incident state.

## Highlights

- Enable Telegram, email, or both from a private local configuration file.
- Send one failure message and one recovery message per job incident and channel.
- Retry failed delivery on later runs without repeating accepted messages to the
  other channel.
- Require verified HTTPS and SMTP TLS, with optional SMTP authentication.
- Preserve job output and failures; expose notification failures in the journal.
- Keep credentials and delivery state outside Git; leave both channels disabled
  after configuration setup.

## Validation

Unit and local TLS transport checks exercise state transitions, suppression,
independent retries, API/SMTP rejection, SMTP authentication, certificate
validation, private files, shell integration, and exit status propagation.
The existing disposable scheduling acceptance passes through the updated job
wrapper with alert configuration isolated from operator recipients.

Automated tests send no messages to real recipients. A separate operator
exercise confirmed failure receipt in Telegram and Gmail, suppression of a
repeated failed check, and recovery acceptance by both providers. Fixtures also
verify repeated-success suppression and partial-provider outage handling; those
cases were not separately confirmed against live providers.

## Scope

Alerts cover completed local scheduled jobs, including lock failures. They cannot
detect a powered-off host or independently monitor the scheduler. Delivery is
retried on subsequent job runs; it is not an exactly-once durable message queue.
SMTP OAuth, S3 job scheduling, and external monitoring remain outside this change.
