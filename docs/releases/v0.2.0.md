# v0.2.0 — Physical Backup And Restore

Status: draft. Publish after the restore PR is merged and CI passes on `main`.

## Summary

Create and verify PostgreSQL physical backups with pgBackRest, archive required
WAL, and restore a selected full backup into an isolated database volume with
the source stopped.

## Highlights

- PostgreSQL 17.11 with pgBackRest 2.59.1 and a separate local backup repository.
- Explicit backup, inspection, integrity verification, and retention configuration.
- Restore into an empty target from an explicitly selected full backup label.
- Read-only repository mount and disabled archiving on the recovered instance.
- Refusal to overwrite occupied targets and failure detection for missing WAL,
  empty backup sets, and corrupted backup files.
- Documented startup, shutdown, resume, and repeat-restore commands.

## Validation

`make check` and `make acceptance` passed locally. All 20 original orders were
restored exactly, a later source write was excluded, and new recovered-side
writes survived restart. Source records and repository file checksums remained
unchanged by restoration.

See [physical restore evidence](../../evidence/physical-restore-acceptance-20260928.md).
The merged release commit still requires successful GitHub CI before publication.

## Scope And Interpretation

The database, backups, and recovered instance share one Docker host. Restoration
targets the first consistent state of the selected backup. Recovery to a chosen
timestamp, off-host durability, automatic failover, and RPO/RTO measurement are
not included. Retention is configured.
