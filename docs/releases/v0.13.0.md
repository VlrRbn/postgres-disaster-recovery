# v0.13.0 — Patroni Automatic Failover

## Summary

Add a separate local runtime with two Patroni-managed PostgreSQL nodes and
a three-member etcd cluster. Verify automatic leader promotion, former-leader
recovery, and write availability boundaries when DCS quorum changes.

## Highlights

- Add Patroni startup, shutdown, status, and role-aware SQL commands.
- Pin PostgreSQL, Patroni, the psycopg adapter, and the etcd image digest.
- Protect replication, rewind, and Patroni REST traffic with verified TLS.
- Require mutual TLS for etcd client/peer traffic and authentication for REST changes.
- Keep credentials private and isolate data, certificates, and networks from
  the existing manual replication and backup runtimes.
- Record acknowledged-order loss and observed failover time in a JSON report.

## Validation

The disposable scenario checks TLS and REST controls, normal streaming,
one-member etcd loss, leader-container failure, automatic rejoin, majority loss,
quorum restoration, and container recreation. Deliberate replica isolation
measures committed orders missing after asynchronous promotion.

## Scope

All nodes share one Docker host. Watchdog and external fencing are not configured;
container/DCS fault checks do not prove safety under arbitrary process suspension
or host failure. Replication is asynchronous and acknowledged writes can be lost.
A stable application endpoint, HAProxy routing, client retries, and backup
integration for the Patroni cluster remain separate work. Existing backup commands continue
to target their own local/S3 clusters.
